# О чём talk'уют деньги — автопостинг новостей

Раз в час пайплайн берёт свежие заголовки с CNBC, NYT, BBC (RSS) и Bloomberg
(их официальный телеграм-канал), переводит на русский и добавляет короткий
авторский комментарий через Claude API, публикует в канал через Telegram Bot
API. Хостинг — GitHub Actions (бесплатно).

## Разовая настройка

### 1. Секреты репозитория

В **GitHub, в этом репозитории** → вкладка **Settings** → в левом меню
**Secrets and variables** → **Actions** → кнопка **New repository secret**.
Добавить три секрета:

| Имя | Что туда | Где взять |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота-администратора канала | у @BotFather в Telegram, `/mybots` → выбрать бота → API Token |
| `TELEGRAM_CHAT_ID` | `@talkuyut_dengi` (или числовой id канала, если username недоступен боту) | обычно достаточно username канала с `@` |
| `ANTHROPIC_API_KEY` | ключ Anthropic API | [console.anthropic.com](https://console.anthropic.com/) → Settings → API Keys → Create Key |

### 2. Права записи для Actions

Там же, в **GitHub** → **Settings** этого репозитория → в левом меню
**Actions** → **General** → раздел **Workflow permissions** внизу страницы →
выбрать **Read and write permissions** → **Save**.

Это нужно, чтобы workflow мог коммитить обновлённый `state/posted.json`
(список уже опубликованного) обратно в репозиторий после каждого запуска.

### 3. Первый запуск

Первый запуск **ничего не публикует** — он только запоминает все заголовки,
которые видит прямо сейчас в фидах (`bootstrapped: false → true` в
`state/posted.json`). Это специально, чтобы в канал не улетела разом вся
история фидов. Со второго запуска в канал будут уходить только новые
заголовки.

Запустить вручную можно в **GitHub** → вкладка **Actions** → workflow
**«Публикация новостей»** в списке слева → кнопка **Run workflow** справа.
По расписанию (раз в час) он и так будет запускаться сам — `cron` в
`.github/workflows/publish.yml`.

## Локальная проверка перед боевым запуском

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=@talkuyut_dengi ANTHROPIC_API_KEY=...
DRY_RUN=1 python main.py   # печатает готовые посты в консоль, ничего не публикует
```

Если всё выглядит хорошо — убрать `DRY_RUN=1` и прогнать ещё раз (это будет
первый боевой запуск — bootstrap, без публикаций, см. выше), либо просто
дать сработать первому запуску в Actions.

## Добавить/убрать источник

Список источников — в `src/config.py`, список `SOURCES`. Для RSS достаточно
имени и ссылки на фид. Для телеграм-канала (как Bloomberg) — имя канала без
`@`, работает через публичную веб-версию `t.me/s/<канал>`, авторизация не
нужна.

## Известные ограничения

- Расписание GitHub Actions (`schedule`) — это гарантия «не раньше», а не
  «ровно в такое-то время»: в моменты высокой нагрузки на GitHub запуск может
  сдвинуться на несколько минут. На дедуп по `state/posted.json` это не
  влияет.
- `t.me/s/<канал>` — не официальный API, а публичная HTML-страница
  предпросмотра. Работает стабильно, но при существенном изменении вёрстки
  Telegram может потребоваться поправить `src/sources.py`.
- Если один и тот же инфоповод выходит у нескольких источников почти
  одновременно — пайплайн пока не дедуплицирует по смыслу, только по
  конкретной ссылке. Это можно добавить позже (например, сравнение похожести
  заголовков), если начнёт мешать.
